## Q1. Does a `SimulationStep` callback exist for TM2020? What physics-step-adjacent callbacks exist, with exact signatures and introducing version?

### Takeaway
Yes. `void SimulationStep()` is a documented Openplanet plugin callback, "Called every physics simulation step", and the Trackmania download changelog records it as added in **Openplanet 1.29.14 for Trackmania** (listed "2 months ago" as of 2026-10-20, i.e., roughly August 2026; the same release adds game-version data for 2026-07-22). The docs say nothing about ordering relative to input sampling/physics integration, synchronicity, vehicle count, countdown/pause/replay behavior, or forbidden operations; all of that is UNVERIFIED.

### Cited Findings
- The callbacks reference page lists `void SimulationStep()` with the text (verbatim per fetch): "Called every physics simulation step. Please be careful with this function: your code needs to be very performant here," "as this may be called multiple times per frame." Page footer: "Page updated 1 month ago by Miss". **[DOC]** — [Plugin callbacks](https://openplanet.dev/docs/reference/plugin-callbacks)
- Full list of callbacks on that page (signatures as documented): `void Main()` ("Main entry point. Yieldable." — the only callback marked yieldable); `void Render()` ("Render function called every frame."); `void RenderInterface()`; `void RenderMenu()`; `void RenderMenuMain()`; `void RenderSettings()` (Deprecated); `void RenderEarly()` ("Same as `Render()`, but called before every other plugin's (regular) rendering functions." "_It's unlikely you will ever need to use this callback._"); `void Update(float dt)` ("Called every frame. `dt` is the delta time (milliseconds since last frame)."); `void SimulationStep()`; `void OnDisabled()`, `void OnEnabled()`, `void OnDestroyed()`; `void OnSettingsChanged()`, `void OnSettingsSave(Settings::Section& section)`, `void OnSettingsLoad(Settings::Section& section)`; `void OnKeyPress(bool down, VirtualKey key)` and `UI::InputBlocking OnKeyPress(bool down, VirtualKey key)` ("Called whenever a key is pressed on the keyboard."); `void OnMouseButton(bool down, int button, int x, int y)` and `UI::InputBlocking OnMouseButton(...)` ("Called whenever a mouse button is pressed. `x` and `y` are the viewport coordinates."); `void OnMouseMove(int x, int y)`; `void OnMouseWheel(int x, int y)` and `UI::InputBlocking OnMouseWheel(int x, int y)`; `void OnProtocolUrl(const string &in path)`; `void OnLoadCallback(CMwNod@ nod)` (requires `RegisterLoadCallback`). **[DOC]** — [Plugin callbacks](https://openplanet.dev/docs/reference/plugin-callbacks)
- No callback named `OnRunStep` or `OnPluginTreeCreated` is on the callbacks page. **[DOC]** — [Plugin callbacks](https://openplanet.dev/docs/reference/plugin-callbacks)
- The callbacks page does not state per-callback game support (TM2020 vs MP4 vs Turbo) or the Openplanet version in which each was added. **[DOC]** — [Plugin callbacks](https://openplanet.dev/docs/reference/plugin-callbacks)
- Trackmania download/changelog page: the **1.29.14 for Trackmania** entry (default branch, "2 months ago") includes the line "Added `SimulationStep()` callback" and "Added game version data for 2026-07-22 (hotfix branch)". `SimulationStep` appears in no other listed version (1.29.5 "6 months ago", 1.29.0 "9 months ago", 1.28.0 "1 year ago", 1.27.12 "1 year ago"); "OnRunStep" and "physics" do not appear anywhere on the page. **[DOC]** — [Downloads for Trackmania](https://openplanet.dev/download/next); permalink for 1.29.14: [/download/version/330](https://openplanet.dev/download/version/330) (page gives no absolute date, only "default 2 months ago").
- The changelog gives no implementation detail for `SimulationStep` (no mention of ordering, thread, or vehicle count). **[DOC]** — [/download/version/330](https://openplanet.dev/download/version/330)
- MLFeed's repo has a commit "fix compilation on 1.29.15" dated Oct 13, 2026, so an Openplanet 1.29.15 exists as of October 2026 (not shown on the default download page I fetched). **[SRC]** — [tm-mlfeed-race-data commits (manialink-base)](https://github.com/XertroV/tm-mlfeed-race-data/commits/manialink-base) (commit `a2341eb`, Oct 13, 2026)
- The TM2020 game-class reference (next.openplanet.dev) is stamped "Documentation from build 2026-01-26 15:06:37". **[DOC]** — [next.openplanet.dev](https://next.openplanet.dev/)

### Inferences
- Because `SimulationStep` only appears in the 1.29.14 changelog for the Trackmania download page, any plugin relying on it must require Openplanet >= 1.29.14; plugins written before mid-2026 (e.g., Dashboard, VehicleState, MLFeed) necessarily use per-frame callbacks (`Update`/`Render`) or ManiaScript hooks instead.
- "May be called multiple times per frame" matches a fixed-step physics loop catching up to render frames; whether it is called zero times during pause/menus is not documented.

- Whether `SimulationStep` is available in MP4/Turbo builds: UNVERIFIED (only the Trackmania download page was checked; the MP4 beta listing mention in search results concerned 1.27.17 and fonts).
- Exact calendar release date of 1.29.14: UNVERIFIED (site shows only "2 months ago").

## Q2. Plugin modes: what do "signed/normal (Regular)", "School Mode", and "Developer Mode" allow/forbid? Can a user write, upload, get signed, and install their own plugin in normal mode? What is the review process?

### Takeaway
Openplanet has four "signature modes": Official (only shipped plugins), Regular (default; shipped + signed user plugins reviewed under the plugin ToS), School (Regular + signed school-mode plugins; blocks online play and official-leaderboard record submission except on whitelisted maps), and Developer (loads unsigned plugins; requires Club Edition; implies School Mode). Signing happens only through upload to openplanet.dev followed by review; the docs do not say whether review is automatic or manual, how long it takes, or whether unlisted/hidden uploads exist.

### Cited Findings
- Signature modes page (updated "three months" before fetch, by Miss): **Official** — "Openplanet will only load plugins officially shipped with Openplanet"; **Regular** — default; loads official plugins plus user-created signed plugins "reviewed and approved by the Openplanet team following its plugin terms of service"; **School** — like Regular plus signed plugins designed for learning; disables leaderboards and online play on most maps; **Developer** — loads all plugins signed or unsigned, and "also enables School Mode". Competition Profiles are additional dynamically-defined modes. **[DOC]** — [Signature modes](https://openplanet.dev/docs/tutorials/signature-modes)
- Developer Mode was introduced in Openplanet **1.24.4** (2022 news post by Miss). "When enabled... Developer Mode lets users run unsigned plugins, which requires Club Edition. When it's off, which is the default, Openplanet only loads signed plugins." Rationale: letting competition hosts limit Openplanet users; detectable via a `[DEVMODE]` tag in Openplanet's system information; developed with the Evo team / EvoSC. "Unsigned plugins can be signed by uploading a new version through the plugin admin page and marking it for signing." **[DOC]** — [Introducing "Developer Mode"](https://openplanet.dev/news/2022/developer-mode)
- School Mode shipped with Openplanet **1.27** (2024 news post by Miss): "prevents you from playing online" and submitting records to official leaderboards, with whitelisted-map exceptions; "Developer mode now also implies School Mode". Motivation: "speed drift helper" plugins that "in some way indicate to the player what to do to hold a perfect speed slide". Nadeo stance quoted: "Ubisoft Nadeo's official stance has been that they don't see an issue with visual helpers" "as long as they don't change the gameplay." **[DOC]** — [Introducing School Mode](https://openplanet.dev/news/2024/introducing-school-mode)
- School Mode developer preview (2024): to be "publicly release[d]... as 1.27.0 when the testing period has concluded"; "We will not be approving school mode plugins just yet." **[DOC]** — [Developer preview for School Mode](https://openplanet.dev/news/2024/school-mode-developer-preview)
- School mode docs page (updated ~2 years before fetch): enable via overlay `Openplanet -> Signature Mode -> School`; "Exiting school mode will disconnect you from any ongoing game"; school-mode plugins "may still affect game state after they stop running". The page does not say how a plugin is marked as a school-mode plugin. **[DOC]** — [School mode](https://openplanet.dev/docs/school-mode)
- Trusted developer page: trusted developers "can bypass school mode restrictions on all maps"; school mode "turns on automatically when developer mode is enabled" and "blocks setting leaderboard times and playing online on most maps"; whitelisted maps = the Openplanet School Campaign (trackmania.io campaign 9/35357) playable on a Nadeo-hosted server in the Openplanet club and an Evo eSports dedicated server; map creators can request whitelisting. Development advice: develop on whitelisted maps, and/or install the signed `.op` from the plugin manager alongside the source folder (same ID; developer mode prefers the source folder). Application is reviewed case by case (regular, well-known community member; reachable on Discord; some dev knowledge). Abuse => flag revoked, possible ban from Openplanet services. **[DOC]** — [Trusted developer](https://openplanet.dev/user/trusted); list of 28 trusted developers (incl. Miss, Phlarx, XertroV, Ezio, skybaks not listed) — [Trusted developers list](https://openplanet.dev/users/trusted)
- Writing-plugins tutorial (updated ~2 years ago by Miss): "In order to write your own plugins, you need Club Edition in Trackmania (2020)"; Developer Mode "by default it is disabled to prevent unsigned plugins from being loaded"; "Plugins have to be "signed" for them to work outside of Developer Mode." "This happens on the website itself as part of the plugin review process." "Simply submit & upload your plugin here and wait for it to be reviewed." "it will only be signed once you upload it to the website and once it has been reviewed." The page does not say whether review is automatic or manual or how long it takes, and does not mention unlisted/hidden/private plugins. **[DOC]** — [Writing plugins](https://openplanet.dev/docs/tutorials/writing-plugins)
- Plugin terms of service (updated ~1 month before fetch, by Miss): rules — no copyrighted material; no NSFW; "Plugins that bypass restrictions into paid game features will not be approved. Developers should use permission checks"; plugins requesting full leaderboards not approved; "Plugins that are mostly AI generated are not allowed"; no cryptocurrency; Openplanet "may unpublish plugins it considers damaging to the game or community, including those that cause game instability". The ToS does **not** mention inputs, physics, automation, memory writes, or a review SLA. **[DOC]** — [Plugin terms of service](https://openplanet.dev/docs/plugin-tos)
- Installing-plugins page (updated ~4 years ago): plugin manager since Openplanet 1.19; `.op` files go in `OpenplanetNext/Plugins`; error "No signature available for script" appears when offline, without Club edition, or with no `.sig`; "Insufficient permissions" means a subscription upgrade is needed — "Some plugins are signed only for the paid Standard edition, not the free Starter edition." **[DOC]** — [Installing plugins](https://openplanet.dev/docs/tutorials/installing-plugins)
- Preprocessor defines for signature level: `SIG_OFFICIAL`, `SIG_REGULAR`, `SIG_SCHOOL`, `SIG_DEVELOPER` are "defined when the **current** signature level is equal or below their respective level" (so `SIG_SCHOOL` is defined in Official, Regular and School levels; `SIG_DEVELOPER` in all). Also `TMNEXT`, `MP4`, `TURBO`, `DEVELOPER` (debug build), `COMP_<ID>` for competition profiles. **[DOC]** — [Preprocessor](https://openplanet.dev/docs/reference/preprocessor)
- `Meta::IsDeveloperMode()` ("Returns true if developer mode is currently enabled."), `Meta::IsSchoolModeWhitelisted()` ("Returns true when the current session is whitelisted by school mode, and school mode is enabled"; use `SIG_SCHOOL` define to check whether school mode is enabled), `Meta::OpenplanetVersion()`, `Meta::OpenplanetVersionDate()`, `Meta::OpenplanetVersionGitCommit()`. **[DOC]** — [Meta API](https://openplanet.dev/docs/api/Meta)
- info.toml: `siteid` "The ID for this plugin on the Openplanet website... The review process normally adds it automatically"; deprecated `perms` key (`free`/`paid`/`full`) replaced by the Permissions API; `supported_games` (from 1.29.10); `controls_other_plugins` (from 1.29.10). No school-mode flag is documented in info.toml. **[DOC]** — [info.toml reference](https://openplanet.dev/docs/reference/info-toml)
- The 2022 post "Allowing visual SD helpers" (by Miss, "4 years ago"): planned to allow "visual speed-drift and ice-slide indicator plugins" for any edition; Nadeo "have confirmed they don't see an issue with these kinds of visual helpers"; "we'll ONLY allow visual helpers. Anything more than that is considered a cheat by Nadeo." The change was then put on hold: "We are delaying this change for now until further notice" after community (mostly FS) feedback; competitions can enforce signature modes via ManiaScript. **[DOC]** — [Allowing visual SD helpers](https://openplanet.dev/news/2022/allowing-visual-sd-helpers)
- Competition Profiles: special signature modes enabling a chosen subset of plugins; the only listed profile "Generic Competition" has an allow rule with an empty list (permits no plugins). **[DOC]** — [Competition Profiles](https://openplanet.dev/competitions)
- Historical: an archived `openplanet-nl/plugin-signing` repo ("The place to request plugin signatures", last updated Feb 8, 2022) shows signing used to be requested via GitHub before the website flow. **[SRC]** — [openplanet-nl repositories](https://github.com/orgs/openplanet-nl/repositories?type=all&page=1)

### Inferences
- A user can write a plugin (needs Club Edition for Developer Mode), upload it, and after review it is signed and installable in Regular mode; the two documented review-rejection axes relevant here are paid-feature bypass and "anything more than visual helpers" (from the 2022 post), not a formal API blacklist.
- Because the "visual SD helpers" liberalisation was put on hold, a plugin whose purpose is to indicate perfect-speed-slide inputs should expect School-Mode-only approval, not Regular signing (inference from the 2022 post plus the 2024 School Mode rationale).

### Gaps
- Whether review is manual, who reviews, typical latency, whether a plugin can be uploaded unlisted/private and still be signed: UNVERIFIED (not on writing-plugins, ToS, or signature-modes pages).
- The concrete rubric reviewers apply to Dev::/memory-writing or physics-touching code: UNVERIFIED (ToS silent; Dev API page has no warnings).
- Exact mechanism by which a plugin is flagged "school mode" at review time: UNVERIFIED.
- No public record found of a specific plugin rejected for touching inputs/physics (searched; see Q11).

## Q3. Permissions system: which `Permissions::` checks exist; which matter for Club vs Starter?

### Takeaway

The docs do not map functions to Starter/Standard/Club tiers; only ads/upgrade helpers name "Standard" and "Club".

### Inferences
- Replay/ghost-related checks a plugin should gate on (by name) are `CreateLocalReplay`, `OpenReplayEditor`, `PlayAgainstReplay`, `PlayRecords`, `ViewRecords`; which of these are false on Starter is not documented here.

## Q4. Input visibility: which classes/properties expose the local player's current inputs in TM2020, and are they read-only?

### Takeaway
Two documented read paths exist: (1) `CSceneVehicleVisState` (render/"vis" state, reached via `CSceneVehicleVis.AsyncState`, typically through the shipped `VehicleState` dependency) with `float InputSteer`, `float InputGasPedal`, `float InputBrakePedal`, `bool InputIsBraking`, `float InputVertical`; (2) the ManiaScript-facing `CSmScriptPlayer` with `const float InputSteer`, `const float InputGasPedal`, `const bool InputIsBraking`. Gamepad raw axes/buttons are exposed read-only via `CInputPort.Script_Pads` -> `CInputScriptPad`. No documented field exposes action-key ("action slot") state or a pre-/post-action-key distinction; the Dashboard plugin page says displayed inputs "are interpolated and not exact".

### Cited Findings
- `CSceneVehicleVisState` (Scene engine, class ID 0x0A00C000, Uninstantiable) members include `float InputSteer`, `bool InputIsBraking`, `float InputGasPedal`, `float InputBrakePedal`, `float InputVertical`, plus `uint RaceStartTime`, `float FrontSpeed`, `vec3 WorldVel`, `uint CurGear`, `float SimulationTimeCoef`, per-wheel fields, `uint8 DiscontinuityCount`, etc. The page shows `const` only on four `*GroundContactMaterial` fields and `Left/Up/Dir`; the Input* fields carry no const marker, and the page gives no descriptions. No "Seed" or "CurRace*" members. **[DOC]** — [CSceneVehicleVisState](https://next.openplanet.dev/Scene/CSceneVehicleVisState)
- `CSceneVehicleVis` (0x0A018000) has `CSceneVehicleVisState@ AsyncState`, `CPlugVehicleVisModel@ Model`, `float Turbo`. **[DOC]** — [CSceneVehicleVis](https://next.openplanet.dev/Scene/CSceneVehicleVis)

## Q9. Does Openplanet provide an input-injection API (`Input::` namespace or hooks that feed inputs to the game)?

### Takeaway
Not found in docs: the Openplanet API index lists no `Input` namespace, `CInputPort`/`CInputScriptPad` expose no injection methods, and the only input-direction primitives documented are `UI::InputBlocking` return values on `OnKeyPress`/`OnMouseButton`/`OnMouseWheel` (block inputs from reaching the game) and generic `Dev::Hook`/`Dev::Write` memory access. ### Cited Findings
